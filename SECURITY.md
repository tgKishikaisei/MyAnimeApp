# Безопасность AniFlow

## Как сообщить об уязвимости

Публичный issue для этого не подходит. Нажмите «Report a vulnerability» на вкладке **Security** или напишите мне в Telegram: [@BehruzAvezmatov](https://t.me/BehruzAvezmatov). Приложите запрос, который воспроизводит проблему, и что он даёт атакующему. Я отвечаю в течение нескольких дней; исправления выходят в ветке `main`.

## Как устроена защита

**Роли.** Регистрация и `PUT /users/me` принимают только безопасные поля (`extra='forbid'`), роль admin выдаёт лишь скрипт `scripts/admin/create_admin.py`. Все админские маршруты висят под одной зависимостью `require_admin`, остальным они отвечают 404. Чужой профиль отдаётся без email и прав.

**Сессии.** Access-токен живёт только в памяти вкладки. Refresh-токен лежит в HttpOnly-cookie с `SameSite=Strict`, в базе хранится его хэш; при каждом обновлении токен меняется, а повторное использование старого отзывает всю цепочку. JWT подписывается PyJWT с явным списком алгоритмов и проверкой `type`, `exp`, `iat`, `jti`. Пароли хэшируются Argon2id. WebSocket подключается по одноразовому билету на 60 секунд, access-токен в URL не попадает.

**Файлы.** Любой путь к медиа проходит `safe_media_path()`: `..`, абсолютные пути и выход за `static/` отклоняются. Загружать можно только картинки и видео из белого списка, с проверкой сигнатуры файла, лимитом размера при потоковом чтении и случайным именем; картинки перекодирует Pillow. ZIP-архивы ограничены по числу клипов и объёму.

**Нагрузка.** Rate limit на вход и тяжёлые эндпоинты (slowapi, Redis), IP берётся только от доверенного прокси. Студия FFmpeg доступна после входа, параметры рендера ограничены, одновременных рендеров не больше `MAX_PARALLEL_RENDERS`.

**Ответы и заголовки.** Ошибки валидации не возвращают присланные данные и не пишут пароли в лог; тексты исключений остаются в логе сервера. nginx отдаёт CSP, `X-Content-Type-Options`, `Referrer-Policy` и `Permissions-Policy`; HSTS ставит внешний прокси с TLS. `/docs` доступен только вне production.

**Инфраструктура.** Контейнеры работают от непривилегированного пользователя на read-only файловой системе без Linux capabilities. Postgres и Redis слушают только внутреннюю сеть, Redis требует пароль, Grafana без анонимного доступа. Зависимости Python зафиксированы с хэшами.

## Автоматические проверки

На каждый push GitHub Actions запускает:

- pytest на PostgreSQL 17, включая 32 теста доступа и сессий из `tests/test_security.py`;
- цепочку миграций `alembic upgrade → check → downgrade` на пустой базе;
- Ruff, bandit и pip-audit для бэкенда;
- `npm audit`, проверку подписей пакетов, `tsc`, ESLint, Vitest и сборку для фронтенда, с проверкой, что в сборке нет source maps и адресов localhost;
- сборку образов и Trivy (Critical и High блокируют);
- gitleaks по всей истории коммитов.
